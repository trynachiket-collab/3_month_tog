    Anatomy of a request URL
    
    
    Hover or tap each part.
    
    
    
      
    
      
    Every part of a URL has a job. In REST, the path names a resource (a thing), and the method says what to do with it.
    
    
    
    
    Good and bad endpoint names
    
    
    
      
    GET /booksPlural noun for the collection. Good.
    
      
    GET /books/7One item, identified by id. Good.
    
      
    GET /books/7/reviewsA nested collection that belongs to book 7. Good.
    
      
    POST /createBookThe verb belongs in the method, not the path. Use POST /books.
    
      
    GET /deleteBook?id=7A GET that changes data breaks the safe rule, and crawlers or prefetchers could trigger it. Use DELETE /books/7.

    What makes an API RESTful
    
  
    REST is an architectural style described by Roy Fielding in 2000, not a protocol or a library. These are the ideas behind it, mapped to what you just did.
    
  
    
    
    Resources
    Everything the API exposes is a thing with an address: /books, /books/3.In this demo: each row in the database is a resource, and each has its own URL.
    
    
    Uniform interface
    The same small set of methods works on every resource, and they mean the same thing everywhere.Once you know DELETE /books/3, you can guess DELETE /authors/3.
    
    
    Representations
    You never touch the database row itself. You get a representation of it, usually JSON, and the Content-Type header says which format.The server could send XML or CSV for the same book if you asked with Accept.
    
    
    Stateless
    Each request carries everything the server needs, including who you are. The server doesn’t remember your previous request.That’s why the token goes in the Authorization header on every single call.
    
    
    Cacheable
    Responses say whether and for how long they can be reused, so clients and proxies can skip repeat work.Look for Cache-Control and ETag on GET responses, and try the 304 status code.
    
    
    Client–server and layered
    The client only knows the URL and the contract. Load balancers, caches and gateways can sit in between without the client noticing.Here the “server” is a JavaScript function, and the client can’t tell.
